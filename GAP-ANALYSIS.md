# Dentiva technical gap analysis — 2026-09-21

## Existing work audited

The original repository contained a small dependency-free HTML/CSS/JavaScript dashboard. It had a responsive visual shell, a first-run clinic-name prompt, localStorage for that one label, no seeded patient data, and a smoke test. It did not contain a desktop runtime, persistence layer, authentication, clinical workflows, financial logic, or Windows packaging. The former preview is retained under `dist/source-preview/` and is explicitly not a release.

## Implemented in this cycle

- Native .NET 8 WPF solution structure (`Dentiva.sln`).
- Core domain entities for clinic, users/RBAC, patients, visits, appointments/serials, treatment plans, odontogram conditions, prescriptions, invoices/payments, expenses, staff, attachments and audit logs.
- EF Core SQLite context with unique/indexed patient codes, invoice numbers and appointment serial conflict protection; decimal monetary precision.
- Local application-data database bootstrap and migration call.
- PBKDF2/HMAC-SHA512 password hashing service with random salt and fixed-time verification.
- First native WPF shell using the Dentiva light clinical design language.
- Windows self-contained publish script, Inno Setup installer configuration, and GitHub Actions Windows workflow.
- Clear preview/release separation.

## Still not implemented

The native shell is not yet a complete commercial product. Patient CRUD screens, MVVM navigation, setup wizard, repository/services, authorization enforcement, clinical editors, persistent queue UI, invoice/payment workflows, attachment service, backup/restore, report/PDF implementation, full localization resources, printer abstraction, migrations generated by EF, comprehensive test suite, and full installer QA remain outstanding.

No native Windows binary has been produced in this Linux environment. Windows printer, DPI, installer, clean-machine and executable QA are pending.
